## Added

- **Flows can launch sessions and chats directly.** The new launch-session and launch-chat nodes start a coding session or an agent workspace chat for each item that reaches them, with no actions.yml entry. A launch-session node works in the item's own repository or in one fixed repository you pick. Each node launches once per item, so a pull request that keeps changing does not start a new session on every update. A launched session's name is capped at 60 characters, falls back to a name from the node and the item when the template renders no letters or digits, and gets a suffix when another session already has it, so `review-{{ .Payload.repo }}` works for every pull request in a repository. The item's detail pane lists the chats it started, beside its sessions.
- **Canvases in Code.** An agent in a Code session can now publish canvases, and the session gets the same canvas pane a chat has, opened from the title bar's right-panel button. Add the server to your agent's own MCP configuration to turn it on: the new Settings ▸ MCP servers page shows each server's address and the setup for Claude Code, Codex, and other agents, and Hive never edits that configuration for you. A session's canvases belong to its repository and are kept in the repository's hive context directory, so every session of the repository shares them and they outlive the session.
- **Canvases open full page.** A canvas now opens over the current view with its canvases in a sidebar, so a long report or a set of linked canvases reads like a small wiki. Open it with **Open full page** in the canvas pane, by picking a canvas in the command palette, or with ⌘⇧P or `g v`. Escape or the shortcut again returns to where you were. A Markdown link that names another canvas opens that canvas in place, in the pane as well. Copy as Markdown, save to a file, and the canvas filter work as they do in the pane. The full-page view and the command palette list Code session canvases beside your workspaces' canvases.
- **Fenced outside content in prompts.** Action and node templates can wrap a PR body, an issue, or a webhook payload in `{{ untrustedStart }}` and `{{ untrustedEnd }}`, so the agent can tell where your instructions stop. `untrustedStart` takes key/value pairs for attributes on the opening tag, and `{{ untrustedNotice }}` explains the fence to the agent. The starter actions, the New Session draft from an item, and the webhook transform prompt now fence the item text this way.

## Changed

- **Hive Desktop honors `HIVE_DATA_DIR`.** If you moved the hive CLI's data root, the app now finds the same sessions and tasks without a second variable. It reads `HIVE_DATA_DIR` from your login shell, so a launch from the Dock sees it too. `HIVE_DESKTOP_HIVE_DATA_DIR` still wins when set.
- **Session names have one set of rules.** A name is unique on its slug, so `Fix Bug` and `fix-bug` count as the same session, and the hive CLI applies the same rules.
- **Pane capture recording is removed.** `tmux.capture_recording` in the hive `config.yaml` no longer does anything, so drop the key. Recordings already under `recordings/tmux` in the hive data directory stay where they are; delete them when you no longer need them.
- **The agent list in onboarding and the Hive settings follows `hive init`'s order**: Claude Code, OpenCode, Codex, Pi, Amp, GitHub Copilot, Cursor.
- **The canvas tools take `session` as text.** It is still `HIVE_AGENT_SESSION` in a chat, and it is the working directory anywhere else. A chat that was open before this update may have a canvas write refused once; relaunch the chat if its agent does not recover.

## Fixed

- **Escape closes only what is on top.** Escape in a Settings drawer no longer also leaves Settings, and Escape in the command palette no longer also closes the Tasks overlay behind it. Keyboard shortcuts no longer fire behind an open drawer or confirmation dialog, and a drawer now takes focus when it opens and returns it when it closes.
- **A CLI-only mistake in the hive config no longer breaks Hive Desktop.** An invalid keybinding or user command in `config.yaml` stopped the app from loading the file and from saving agents and repositories to it, though Hive Desktop never uses those keys. `hive doctor` still reports them.
- **Sessions the hive CLI creates, renames, or removes show in the Code sidebar** without a reload.
- **Shift+Enter inserts a newline in Pi.** The terminal sends Shift+Enter as its own key instead of a plain Enter, so a program that binds it, such as Pi's multi-line prompt, no longer submits the prompt.
- **A package added to `skills.yml` is picked up on save.** A workspace that enabled a package before the package existed kept reporting it as not defined until some other workspace file changed. Saving `skills.yml` now reloads the workspaces like saving `mcps.yaml` or an `agent-workspace.yaml` does.
- **An unknown `settings.yaml` key no longer stops startup.** The key is ignored with a warning, so the updater stays reachable from a file a newer version wrote.
