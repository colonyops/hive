## Added

- **`hive daemon`** (experimental). With `experimental.daemon: true` in the config, one background daemon per data directory creates and deletes sessions and tracks agent status for the TUI, the session commands, and Hive Desktop, so every client shows the same status. A client starts the daemon when none runs; `hive daemon status`, `stop`, and `install` (a launchd agent or systemd user unit) manage it. `hive servers ls` and `hive servers probe` reach daemons on other machines over ssh, listed under `servers:` in the config.
- **Server-qualified session commands** (experimental). `hive session show`, `update`, `delete`, and `recycle` accept `<server>:<id>` for a server listed under `servers:`. An unreachable server's error names the server and includes ssh's reason. Connections allow 30 seconds, risk checks a minute, and deletes 2 minutes; a stuck daemon fails a change before it starts, and shell startup text does not break the connection. Honeycomb remains local: `hive hc list --session` warns that a `<server>:<id>` value matches no items.

## Changed

- **Session JSON names the server.** The `--json` output of `hive session list`, `show`, `info`, and `create` includes a `server` field.

## Fixed

- **Reused clones start a separate session.** The new session gets its own ID, creation time, and inbox without inheriting the previous session's unread messages, group, or `hc` tasks. `hive batch` now honors `session_id` when it reuses a clone. The recycled session's ID stops resolving when its clone is reused, and an `hc` task still assigned to that ID stays assigned until you run `hive hc update <id> --unassign`.
- **Command errors go to stderr**, so stdout stays clean for scripts that read `--json` output.
