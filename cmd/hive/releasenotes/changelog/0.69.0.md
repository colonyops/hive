## Added

- **Session commands on servers** (experimental). `hive new`, `hive session create`, `show`, `list`, `update`, `delete`, and `recycle` take `--server <name>` (or `HIVE_SERVER`) to act on a server under `servers:` in `config.yaml`. Use `--server local` for this machine. With servers configured, `hive session list` shows local and server sessions in one table with a SERVER column, and warns about a server that does not answer instead of failing.
- **Attach to a local or server session.** `hive session attach <[server:]id>` opens a session's terminal and starts it first when its tmux session has ended. A session on a server opens over ssh, in a new local tmux window when you run it inside tmux. `hive new --server` attaches the same way.
- **`hive dt tab`, `panel`, `split`, and `layout`** control the tabs and panels beside a chat or Code session in Hive Desktop: open Drive, Diff, Tasks, or a terminal, move and focus tabs, close panels, resize and turn splits, and print the layout as JSON. The CLI finds the app through its endpoint file, or `--url`.
- **Per-server read and connect limits.** A `servers:` entry in `config.yaml` can set `read_timeout` and `connect_timeout` for a slow link. The defaults stay at 10s and 30s.

## Changed

- **Session line counts include uncommitted work.** They compare the working tree with the merge base of the default branch, rather than committed work alone.
- **Hive no longer runs `spawn` and `batch_spawn` rules.** A session always starts from the `windows` of its rule, or the default layout. A config that still sets these keys keeps loading, and hive logs a warning for each such rule. Move any commands you need into `windows`.

## Fixed

- **tmux windows started by an agent no longer count as agents.** A process started from inside Claude Code, such as a dev server or a shell, no longer shows as a running agent in the TUI's session tree. Idle shells on Linux servers no longer count as agents either.
